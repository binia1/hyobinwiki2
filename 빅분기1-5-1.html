01 데이터 수집

데이터 처리 시스템에 들어갈 데이터를 모으는 과정으로 여러 장소에 있는 데이터를 한 곳으로 모으는 것이다.

1) 데이터 수집 수행 자료

  • 용어집, 서비스 흐름도, 업무 매뉴얼, 데이터 명세서, 데이터 수집 계획서
  • 원천 데이터 담당자 정보, 비즈니스 및 원천 데이터 파악을 위한 비즈니스 모델, 원천 데이터 소유 기관 정보
  • 데이터 수집 기술 매뉴얼, 인프라 구성도, 소프트웨어 아키텍처 개념도, 수집 솔루션 매뉴얼, 하둡 오퍼레이션 매뉴얼

※ 하둡(Hadoop): 다수의 컴퓨터를 마치 하나인 것처럼 묶어 대용량 데이터를 처리하는 오픈소스 프레임워크 [1]

2) 비즈니스 도메인과 원천 데이터 정보 수집

  • ① 비즈니스 도메인 정보: 비즈니스 모델, 용어집, 비즈니스 프로세스(전개에 필요한 모든 순차적/병렬적 활동의 집합)로부터 정보를 습득한다. 전문가 인터뷰로 데이터 종류, 특징 정보를 얻는다.
  • ② 원천 데이터 정보: 수집 가능성, 보안, 정확성을 탐색하고 난이도, 비용 등 기초 자료를 수집한다.

3) 내·외부 데이터 수집

  • ① 데이터의 종류:
    • 내부 데이터: 조직 내부의 서비스 시스템, 네트워크, 서버 장비, ERP, CRM[2] 등에서 생성.
    • 외부 데이터: 소셜 데이터, 특정 기관 데이터, M2M, LOD[3] 등으로 분류.
  • ② 데이터의 수집 주기: 내부 데이터는 실시간 수집 가능. 외부 데이터는 일괄 수집일지 일정 주기일지 정책을 정해야 한다.
  • ③ 데이터의 수집 방법: 내부 데이터는 분석에 적합한 정형화된 형식이 많아 가공 노력이 적다. 외부 데이터는 분석 목표에 맞게 탐색하고 변환하는 노력이 필요하다. (최근 데이터 거래소를 통한 유통도 활발함)
💡 [효빈위키 기적의 TIP & 개념 해설] 창전선 심세이의 일침
  • 데이터 수집 절차, 은근히 발목 잡는다?
    솔직히 자료분석론이나 통계학 교양에서 A+ 찍어본 사람들도 이 '수집' 단계에서 은근히 헷갈려 해. 특히 사회복지조사론 같은 전공 과목에서 깐깐한 교수님 만나면 삐끗해서 B0 폭격을 맞기 딱 좋지. 경험담 아님. 아무튼 아님. 그러니까 시스템 구축 절차 5단계 흐름도는 눈에 꼭 발라두자.
  • 출제 포인트: 내부 데이터와 외부 데이터를 구분하는 표는 시험 단골 손님이야. ERP(전사적자원관리), CRM(고객관계관리)이 '내부'라는 점, 그리고 M2M(사물통신), LOD(개방형 연결 데이터)가 '외부'라는 점을 확실히 외워둬야 해!

4) 데이터 수집 기술

① 데이터 유형별 데이터 수집 기술

② ETL (Extract Transform Load)

하나 이상의 데이터 소스로부터 데이터 웨어하우스(DW), 통합, 마이그레이션[4] 등을 위한 핵심 기술이다.

③ FTP(File Transfer Protocol)

대량의 파일을 네트워크를 통해 빠른 속도로 한꺼번에 주고받을 때 사용되는 파일 전송 서비스이다. TCP/IP 위에서 동작하며, 두 개의 연결(제어 연결, 전송 연결)을 생성한다.[5]

④ 아파치 스쿱(Sqoop) 기술 (정형 데이터)

관계형 데이터베이스(MySQL, Oracle 등)와 하둡 파일시스템(HDFS, Hive, Hbase) 간에 대량 데이터를 전송하는 도구이다. 데이터 가져오기/내보내기 과정을 맵리듀스(MapReduce)를 통해 병렬 처리하며 장애에 강하다. 모든 적재 과정을 자동화한다.

⑤ 아파치 플럼(Flume) 기술 (로그/센서 비정형 데이터)

대용량의 로그 데이터를 효과적으로 수집, 집계, 이동시키는 신뢰성 있는 분산 스트리밍 서비스이다. 하나의 에이전트는 소스(Source), 채널(Channel), 싱크(Sink)로 구성된다.[6]

⑥ 스크래피(Scrapy) 기술 (웹/소셜 데이터)

웹사이트를 크롤링하고 구조화된 데이터를 수집하는 파이썬(Python) 기반의 오픈소스 웹 크롤링 프레임워크이다. 스크랩 과정이 단순하며 한 번에 여러 페이지를 불러오기 수월하다.

💡 [효빈위키 기적의 TIP & 개념 해설] 1호선 고나미의 암기 요약
  • FTP 포트 번호, 은근 헷갈리지? 21번은 제어(명령어 치는 곳), 20번은 데이터(진짜 파일이 오가는 곳). 웹 호스팅 서버나 리눅스 다룰 때 방화벽 열어본 경험이 있다면 21번 포트가 얼마나 익숙한 숫자인지 알 수 있어.
  • 스쿱(Sqoop) = SQL to Hadoop: 정형 데이터베이스(RDB)와 하둡을 이어주는 마법의 징검다리야. SQL의 'S'와 Hadoop의 'oop'가 합쳐졌다고 생각하면 외우기 쉽지?
  • 플럼(Flume) = 소스 ➡️ 채널 ➡️ 싱크: 수도관을 생각하면 돼! 물이 들어오는 곳(Source), 지나가는 파이프(Channel), 빠져나가는 곳(Sink).
  • 스크래피(Scrapy) 🕷️: 파이썬 유저의 영원한 친구. 효빈위키에 효빈광역시 버스 노선도 데이터나 행사 스케줄 자동화해서 긁어올 때 이거 쓰면 꿀잼일지도? 시험에선 '파이썬 기반 웹 크롤링' 키워드만 보면 바로 찍어!
✔️ 개념 체크 (섹션 1)

Q1. 다음 데이터 수집 기술에 대한 설명으로 옳은 것은?
① ETL은 소스 데이터의 형식과 내용을 그대로 유지하여 목표시스템으로 데이터를 이동시킨다.
② 아파치 스쿱(Sqoop)은 스트리밍 데이터 처리에 적합하며, 로그나 네트워크 데이터를 수집하는데 사용된다.
③ 아파치 플럼(Flume)은 관계형 데이터베이스의 데이터를 HBASE, HIVE, HDFS로 가져오는데 사용된다.
④ 스크래피(Scrapy)는 파이썬 기반의 프레임워크로 주로 웹사이트를 크롤링하는데 사용된다.

[정답 및 해설] ④
- ① ETL은 소스 데이터를 정제, 표준화, 통합 등의 과정을 거쳐 변환(Transform)한 후 저장합니다. (그대로 유지 X)
- ② 스쿱(Sqoop)은 정형 데이터 처리를 위해 사용되며, 로그나 스트리밍 데이터는 플럼(Flume)이 처리합니다. (서로 설명이 바뀜)
- ③ 관계형 데이터베이스(RDB)에서 하둡으로 데이터를 가져오는 것은 스쿱(Sqoop)입니다.

Q2. 관계형 데이터베이스로부터 데이터를 추출하는데 사용되는 기술로 틀린 것은?
① ETL
② 스쿱(Sqoop)
③ API
④ 크롤링

[정답 및 해설] ④
크롤링 또는 스크래핑(Scraping)은 관계형 DB가 아니라 웹페이지(HTML 등 비정형 데이터)를 그대로 가져온 후 데이터를 추출하는 기술입니다.

02 데이터 유형 및 속성 파악

1) 데이터 수집 세부 계획 작성

데이터 선정 이후, 유형, 위치, 크기, 저장방식, 수집 기술, 수집주기, 이관 절차, 확보비용 등을 파악하여 세부 계획서를 작성한다. 적절성 검증 방식을 수립하고 재수집 또는 가공 조치를 취한다.

2) 데이터 유형과 위치 및 비용

  • 데이터 유형: 정형 데이터 (RDB 등), 반정형 데이터, 비정형 데이터
  • 데이터 위치: 내부 데이터, 외부 데이터
  • 확보 비용 산정: 데이터 크기, 주기, 기술, 수집 방식, 데이터 가치를 고려.

3) 수집되는 데이터 형태 (반정형의 대표주자들)

  • HTML: 웹 페이지 문서 형식 (텍스트, 태그, 스크립트 구성).
  • XML: 데이터를 표현하기 위해 태그(tag)를 사용하는 다목적 마크업 언어.
  • JSON: 자바스크립트 객체 형식으로 자료를 표현하는 경량의 데이터 교환 방식.
🎒 [효빈위키 팩폭 해설] 3호선 라미가 알려주는 정형/비정형 꿀팁!
  • 반정형 데이터 (HTML, XML, JSON): 웹 개발 해봤다면 지긋지긋하게 봤을 놈들! 데이터 안에 메타데이터(태그나 키값)가 포함되어 있어서 구조는 있지만, 엑셀처럼 깐깐한 표 형태는 아닌 것들이야. 특히 JSON에서 "8진수, 16진수 표현은 지원하지 않는다"는 문장은 은근히 함정 보기로 나오기 좋으니까 꼭 체크해 둬!
  • 비정형 데이터: 텍스트, 동영상, 이미지, 음성 파일. 형태가 없으니 무조건 비정형.
  • 외부 데이터는 가공이 빡세다?: 회사 내부 데이터는 이미 잘 정리된 표라서 쓰기 편하지만, 공공데이터 포털에서 긁어온 외부 데이터는 형태도 제각각이고 오타도 많아서 추가 가공 작업(전처리)이 빡세. 고생 끝에 낙이 온다는 학계의 정설.

4) 데이터 저장 방식

  • 파일 시스템: 데이터를 일정한 규칙으로 파일에 명명하고 위치를 지정.
  • 관계형 데이터베이스 (RDBMS): 성격에 따라 여러 칼럼을 포함하는 정형화된 테이블 집합체.
  • 분산처리 데이터베이스: 데이터 집합이 여러 물리적 위치에 분산 배치되어 저장됨.

5) 데이터 적절성 검증 6단계

크롤링해서 데이터를 끌어모았어도 쓰레기가 섞여 있으면 안 된다. 수집 직후 반드시 검증해야 한다.

  • ① 데이터 누락 점검: 누락/결측 여부 판단하여 재수집.
  • ② 소스 데이터와 비교: 소스 데이터와의 사이즈 및 개수 일치 여부 비교.
  • ③ 데이터의 정확성 점검: 유효하지 않은 데이터 존재 여부 점검. (메타데이터나 패턴 규칙을 통해 오류를 식별).
  • ④ 보안 사항 점검: 수집 데이터에 개인정보 등 민감 정보 유무 확인.
  • ⑤ 저작권 점검: 법률적 검토 수행. (무단 불펌하면 잡혀간다.)
  • ⑥ 대량 트래픽 발생 여부: 네트워크에 과도한 부하(트래픽)를 발생시키는지 검증.
✔️ 개념 체크 (섹션 2)

Q. 수집한 데이터의 적절성 검증에 대한 설명 중 틀린 것은?
① 수집 데이터 세트의 누락, 결측 여부를 판단하여 누락 발생 시 재수집한다.
② 수집 데이터와 소스 데이터의 사이즈 및 개수를 비교 검증한다.
③ 유효하지 않는 데이터는 데이터의 중복 검사를 통해 확인할 수 있다.
④ 개인정보 데이터 발견 시 개인정보 비식별화 필요성을 표시한다.

[정답 및 해설] ③
유효하지 않은 정보는 단순한 '중복 검사'가 아니라, 메타데이터나 데이터에 정의된 규칙들, 일정한 패턴 검사를 통해 패턴이 틀린 오류 데이터 값을 식별하는 방법을 사용해야 합니다. 중복 검사는 그저 똑같은 게 또 있는지만 보는 것입니다.

03 데이터 변환 (Data Transformation)

1) 데이터 변환의 종류 및 수행 자료

데이터를 하나의 표현 형식에서 다른 형식으로 변형(구조적 형태로 전환)하는 과정이다.

  • 비정형 데이터를 정형 데이터 형태(관계형 DB)로 저장
  • 분산파일시스템(HDFS 등)으로 저장
  • 시계열적/주제별 저장 (데이터 웨어하우스)
  • 키-값 형태로 저장 (NoSQL)[7]

2) 데이터베이스 구조 설계 (4단계)

수집 데이터를 바로 HDFS에 저장할 수도 있고, 파이썬(Python)이나 루비(Ruby)[8] 등으로 변환 과정을 거쳐 DB에 저장하기도 한다.

웹 개발이나 자동화 좀 굴려봤다면 너무나도 친숙할 그 이름, 파이썬이 등장했네요. 실제로 크롤링한 뒤죽박죽 비정형 데이터를 깔끔한 표(RDB)에 쑤셔 넣기 전에 파이썬으로 이리저리 데이터 변환(가공)을 하는 건 숨 쉬듯이 하는 작업이죠. 비정형, 반정형 데이터를 분석하기 쉽게 정형화된 데이터베이스로 변환하는 데에 집중해야 한다는 점이 이 파트의 핵심입니다!

3) 비정형/반정형 데이터의 변환

데이터 전처리/후처리가 수행되기 전에 구조적 형태로 전환하여 저장하는 과정이다.

  1. 수집 데이터 속성 구조 파악: title, votes, body 등 구조를 정의하고 적절한 변수명 구분.
  2. 수행 코드 정의: 정보 위치 파악 후 데이터 추출 (파이썬 등 활용).
  3. 데이터 저장 프로그램 작성: 생성된 DB 테이블에 수집 데이터를 저장하는 로직 작성.
  4. 데이터베이스에 저장: DB 테이블로 최종 수집 데이터 Insert.

4) 융합 데이터베이스 설계

구조화된 형태로 수집, 저장된 데이터의 의미를 파악하여 활용 목적별 융합 DB로 재구성한다.

  • 요구사항 분석: 어떤 데이터 속성이 필요한지, 개인정보/민감정보 포함 여부 식별.
  • 데이터 표준화와 모델링 수행: 다양한 데이터 소스 표준화(표준 코드, 용어, 도메인). 엔터티[9]와 애트리뷰트를 추출하여 관계를 정의하는 개념적 설계(ER 다이어그램)와 이를 매핑하여 스키마[10]를 짜는 논리적 설계를 수행한다.

각주

  • [1] 하둡(Hadoop): 다수의 컴퓨터를 마치 하나인 것처럼 묶어 대용량 데이터를 처리하는 오픈소스 프레임워크.
  • [2] ERP(Enterprise Resource Planning): 전사적 자원 관리.
  • [3] LOD(Linked Open Data): 웹에서 누구나 사용할 수 있도록 무료로 공개되는 연계 데이터.
  • [4] 마이그레이션(Migration): 하나의 운영환경으로부터 더 나은 운영환경으로 데이터를 옮기는 과정.
  • [5] FTP 제어 연결은 21번 포트, 데이터 전송 연결은 20번 포트를 주로 사용한다.
  • [6] 아파치 플럼(Flume): 분산 환경에서 대량의 로그 데이터를 효과적으로 수집, 전송하는 분산 스트리밍 서비스.
  • [7] NoSQL: 빅데이터 처리를 위한 비관계형 DBMS. 대규모 수평적 확장성이 특징이다.
  • [8] 루비(Ruby): 마츠모토 유키히로가 발표한 스크립트 언어. 파이썬과 주로 비교되며 일본에서 많이 사용된다.
  • [9] 엔터티(Entity): 인간이 생각하는 개념, 의미있는 정보의 단위.
  • [10] 스키마(Schema): 데이터베이스의 논리적, 물리적 구조를 기술한 것.
