1. 데이터 나누기: 왜 나누고, stratify는 무엇일까?

2유형은 우리가 만든 모델이 미래의 데이터를 얼마나 잘 맞출지 평가하는 시험입니다. 하지만 우리에겐 미래의 정답이 없죠.
그래서 가지고 있는 '과거의 문제집(train 데이터)' 중 20%를 찢어서 "미니 모의고사(검증용, validation)"로 빼두는 작업이 train_test_split입니다.

  • random_state=42: 이걸 안 쓰면 실행할 때마다 찢어내는 모의고사 페이지가 바뀝니다. 점수가 계속 요동치겠죠? 결과를 재현하기 위해 고정합니다.
  • 순서 주의: x_tr, x_va, y_tr, y_va 순서로 무조건 받아야 합니다. (X학습, X모의, Y학습, Y모의)
  • stratify=y (비율 맞추기 마법):
    예를 들어 아이돌 팬클럽 데이터(train)에 '탈퇴한 팬(1)'이 30%라고 칩시다. 그냥 랜덤으로 찢으면 재수 없게 모의고사(validation) 쪽에 탈퇴 팬이 50%나 몰릴 수도 있습니다.
    stratify=y를 걸어주면, 학습용에도 30%, 모의고사용에도 30%가 되도록 아주 공평하게 비율을 맞춰서 찢어줍니다! (분류 문제의 국룰입니다.)

2. 데이터 누수(Leakage): 평가 데이터에 fit 하지 마라!

🚨 "강사님, 전체 데이터를 한꺼번에 스케일링(StandardScaler)하면 안 되나요? 코드가 편한데."
-> 안 됩니다! 그것이 바로 데이터 누수(미리보기 부정행위)입니다.

fit이라는 명령은 "이 데이터의 힌트(평균, 최대/최솟값)를 외워라!"입니다. 만약 시험지(검증용/평가용)까지 싹 다 합쳐서 fit을 해버리면, 모델이 풀기도 전에 시험지의 전체 평균(힌트)을 미리 알고 문제를 푸는 꼴이 됩니다. 진짜 실력이 아닌 거죠.

명심하세요!
1. fit(힌트 외우기)은 오직 학습용(train)에만 한다!
2. 검증용(val)과 실전용(test) 데이터에는 학습용에서 외운 기준을 그대로 transform(적용)만 시킨다!

[실습 2] 부정행위(전체 fit)와 정상(학습만 fit)의 미세한 값 차이 증명

3. 범주형 인코딩: OrdinalEncoder vs get_dummies

머신러닝 모델은 글자("남", "premium")를 보면 토를 합니다. 이걸 숫자로 먹여주는 과정이 인코딩입니다.

💡 실기 꿀팁: 두 개 중 대체 어떤 걸 써야 하나요?
- get_dummies (원핫인코딩): 범주형 변수의 고유값 종류가 적을 때 직관적이고 편합니다. 단, train과 test 세트를 미리 하나로 합쳐서(concat) 적용해야 열 개수 불일치 에러를 막을 수 있습니다.
- OrdinalEncoder (라벨인코딩): 범주 종류가 아주 많거나, test 데이터에만 처음 보는 이상한 글자(신규 카테고리)가 등장할 위험이 있을 때 강력한 방어력(unknown_value=-1)을 발휘합니다.
  • pd.get_dummies() (원-핫 인코딩): "요금제_premium", "요금제_basic" 이라는 O/X 체크리스트 열을 무식하게 다 만들어버립니다. 성능은 좋지만, 학습할 때 없던 요금제가 실전(test)에 나오면 열 개수가 안 맞아서 대참사(에러)가 납니다.
  • OrdinalEncoder(): 하나의 열 안에서 basic=0, premium=1, standard=2 로 깔끔하게 숫자로 바꿔버립니다. 여러 열을 한 번에 바꿀 수 있어 강력합니다.
  • 최강의 방어력 handle_unknown="use_encoded_value", unknown_value=-1: 실전(test) 파일에서 갑자기 'VIP'라는 처음 보는 글자가 등장하면 어떻게 될까요? 원래는 에러가 나면서 0점이 되지만, 이 옵션을 켜두면 "모르는 글자네? 묻지도 따지지도 말고 -1 번 줘버려!" 하고 무사히 시험을 통과시켜 줍니다. (필수 암기)

4. 분류 모델: predict(라벨) vs predict_proba(확률)

모델(국밥 랜덤포레스트)을 학습(fit)시킨 후, 정답을 외칠 차례입니다.

  • model.predict(X): "이 녀석은 이탈한다(1)!", "얘는 남는다(0)!" 단호하게 찍습니다. (분류 결과 제출용)
  • model.predict_proba(X): "얘가 이탈할 확률은 78%고, 남을 확률은 22%입니다." 라고 소심하게 양쪽 확률을 다 알려줍니다.
  • 보통 우리가 원하는 건 '이탈(1)할 확률' 이므로, 반환된 두 개의 열(0일 확률, 1일 확률) 중 두 번째 열(인덱스 1)을 [:, 1] 로 쏙 빼서 가져옵니다.
[실습 4] 단호박 predict vs 소심한 확률 predict_proba

5. ROC AUC: 왜 정답(라벨) 대신 확률을 제출해야 할까?

빅분기 실기 분류 문제의 채점 기준은 90% 이상이 ROC AUC 입니다.
AUC는 단순히 "몇 개 맞혔냐(정확도)"가 아니라, "이탈할 놈들을 1등부터 꼴찌까지 얼마나 잘 줄 세웠냐(순위)"를 채점합니다.

※ 간혹 출제되는 F1-Score 와의 차이점
가끔 문제에서 ROC AUC가 아닌 f1_score나 accuracy_score(정확도)를 요구할 때가 있습니다. 이때는 확률(predict_proba)이 아니라 반드시 단호박 라벨(predict)을 제출해야 합니다!
- 평가지표가 ROC AUC ➡️ 확률 제출 predict_proba()[:, 1]
- 평가지표가 F1, Accuracy ➡️ 라벨 제출 predict()
💡 만약 predict로 0과 1만 딱 제출해 버리면?
모두가 공동 1등(1), 공동 꼴찌(0)가 되어버려서 세밀한 순위(누가 더 찐으로 위험한지) 정보가 뭉개집니다!
그래서 AUC 지표를 채점할 때는 반드시 predict_proba를 쓴 섬세한 확률(0.89, 0.45 등)을 제출해야 점수가 훨씬 높게 나옵니다.

6. 회귀 모델과 RMSE (squared=False의 폐지)

이번엔 0/1이 아니라 끝없는 숫자(자전거 대여량, 콘서트 굿즈 매출액 등)를 맞추는 회귀(Regression) 문제입니다. 모델도 RandomForestRegressor를 씁니다.

  • RMSE (평균제곱근오차): 내가 맞춘 값이 실제 정답에서 평균적으로 얼마나 빗나갔는지를 알려줍니다. 낮을수록 만점입니다.
  • R² (설명력): 1에 가까울수록 내 모델이 정답을 완벽하게 설명한다는 뜻입니다. (0이면 그냥 평균값으로 막 찍은 수준)
  • ★ 극도로 중요한 변경점 ★: 예전 교재들에는 mean_squared_error(y, p, squared=False)를 쓰라고 되어있지만, 최신 파이썬 버전에서는 이 문법이 폐지(삭제)되었습니다! 그대로 쓰면 에러 뿜고 장렬히 전사합니다.
    check = pd.read_csv("result.csv") print("1. 생성된 파일 모양 (행 개수가 test파일과 맞는지 확인):", check.shape) print("2. 생성된 열 이름 (pred 하나만 있어야 함!):", check.columns.tolist()) print("3. 이탈 확률 3명 미리보기:\n", check.head(3).round(4))
