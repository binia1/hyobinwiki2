1. 계층형 질의(Hierarchical Query) 개념 및 실행 순서

코사카 호노카 : "우미 쨩! 우미 쨩! 우리 뮤즈(μ's) 조직도를 보니까, 'M000(호노카)' 밑에 'M001(우미)', 'M002(코토리)'가 있고... 또 니코 쨩 밑에 마키랑 하나요가 묶여있는데... 이걸 상하 관계로 쫙! 뽑아내려면 조인(JOIN)을 아홉 번이나 해야 해?! 나 빵 먹을 시간도 없단 말이야!"

소노다 우미 : "하아... 호노카!!! 그럴 땐 조인이 아니라 오라클의 계층형 쿼리(Hierarchical Query)를 써야 합니다! 하나의 테이블 안에 부모-자식 관계가 존재할 때, 트리(Tree) 형태로 단번에 전개해주는 훌륭한 문법이지요. 연습도 안 하고 조인만 남발하다간 파렴치한 쿼리가 되고 맙니다! 러브 애로우 슛!"

쿠로사와 다이아 : "뿟부- 데스와!! 여기서 가장 중요한 건 PRIOR 키워드의 위치입니다! 교과서에 명시된 대로, PRIOR가 자식 컬럼(PK)에 붙으면 아래로 뻗어가는 순방향(Top-Down), 부모 컬럼(FK)에 붙으면 위로 거슬러 올라가는 역방향(Bottom-Up)이 됩니다. 이걸 틀리면 학생회장으로서 용서하지 않겠어요!"

미후네 시오리코 : "한 가지 더! 효빈광역시 지선버스(#37B484)처럼 한 치의 오차도 없는 질서 유지를 위해 실행 순서를 반드시 외우셔야 합니다. 계층형 쿼리는 FROM(테이블) → START WITH(시작점) → CONNECT BY(전개) → WHERE(필터링) → SELECT(조회) 순으로 실행됩니다. 전개가 완전히 끝난 뒤에 필터링(WHERE)을 수행한다는 점을 명심하십시오!"

계층형 쿼리의 뼈대와 문법 규칙은 다음과 같다.

SELECT 컬럼명, LEVEL
FROM 테이블명
START WITH 시작조건 -- 1. 계층 구조 전개의 시작점(Root 노드) 지정
CONNECT BY [NOCYCLE] PRIOR 연결조건 -- 2. 자식 노드로 뻗어나갈 조건 설정
[WHERE 필터조건] -- 3. 전개가 완료된 후 마지막에 대상 필터링!
[ORDER SIBLINGS BY 정렬컬럼] -- 4. 형제 노드(동일 레벨) 간의 정렬
  • START WITH: 트리의 꼭대기(Root)가 될 데이터를 찾는다. (예: START WITH 직속선배ID IS NULL -> 직속 선배가 없는 녀석이 루트!)
  • 순방향 전개 (Top-Down): 부모 노드에서 자식 노드 방향으로 전개. PRIOR 부모 컬럼 = 자식 컬럼 형태로 작성한다. (PRIOR가 자식 쪽에 없는 거 같지만 문맥상 부모가 자식을 부르는 순방향! 시험 단골 출제!)
  • 역방향 전개 (Bottom-Up): 자식 노드에서 부모 노드 방향(위쪽)으로 전개. PRIOR 자식 컬럼 = 부모 컬럼 형태로 작성한다.
-- [교과서 완벽 반영 예시] 뮤즈(μ's) 조직도 테이블 순방향 전개 SELECT LEVEL, 멤버ID, 직속선배ID, 멤버이름 FROM 스쿨아이돌_조직 START WITH 직속선배ID IS NULL -- M000(호노카)이 시작점(Root)이 됨 CONNECT BY PRIOR 멤버ID = 직속선배ID -- (부모의)멤버ID = (자식의)직속선배ID -> 순방향! ORDER SIBLINGS BY 멤버ID ASC; -- 같은 계층(LEVEL)끼리 ID순 정렬
[우미의 특별 러브 애로우 슛! 💘 재미있는 계층형 쿼리 비유]

[실전 기출 1] 계층 쿼리 실행 순서

Q. (우미 출제) 계층형 쿼리에서 필터링(WHERE 절)은 어느 시점에 수행됩니까? 기본도 모르면 혹독한 트레이닝입니다!

  1. 테이블을 조회(FROM)하기 직전
  2. 계층의 시작 위치(START WITH)를 찾을 때 동시에
  3. 계층 전개(CONNECT BY)가 완전히 끝난 직후
  4. 데이터 정렬(ORDER SIBLINGS BY)이 끝난 후
[우미 해설] 정답은 3번입니다. 교과서에 명시된 실행 순서는 FROM → START WITH → CONNECT BY → WHERE → SELECT 입니다. 전개가 일단 완료되고 나서 필터링을 수행한다는 점을 잊지 마세요!
[실전 기출 2] PRIOR 방향성 함정

Q. (다이아 출제) 아래 질의는 어떤 방향으로 계층 전개가 이루어집니까?
START WITH 멤버ID = 'M007'
CONNECT BY 멤버ID = PRIOR 직속선배ID;

  1. 순방향 (부모 → 자식)
  2. 역방향 (자식 → 부모)
  3. 사이클 전개
  4. 전개 불가능
[다이아 해설] 정답은 2번입니다! PRIOR 키워드가 '직속선배ID(부모 컬럼, FK)'에 붙어 있습니다. 즉, 자식 컬럼 = PRIOR 부모 컬럼의 형태가 되므로 마키(M007)에서 시작하여 니코, 호노카로 거슬러 올라가는 역방향 전개(Bottom-Up)가 정답입니다.

2. 계층형 쿼리 전용 가상 컬럼 및 제공 함수

나카스 카스미 : "꺄룽~☆ 선배님! 계층 쿼리를 돌렸더니, 카스밍이 동호회에서 몇 번째 짬찌(...가 아니라 귀여운 후배!)인지 레벨을 알려주고, 카스밍 밑에 귀여운 후배가 한 명도 없는 막내(Leaf)인지 아닌지를 큐트하게 알려주는 기능은 없나요?!"

엠마 베르데 : "카스미 쨩, 너무 귀엽다~ 오라클은 가상 컬럼(Pseudo Column)과 전용 함수들을 제공해주거든. LEVEL로 기수(Depth)를 확인하고, CONNECT_BY_ISLEAF로 막내인지 아닌지 0과 1로 반환해 준단다. 그리고 CONNECT_BY_ROOT를 쓰면 지금 속한 계층의 가장 꼭대기(루트)에 있는 사람이 누군지 한 번에 알 수 있어! 포근하게 전체를 감싸주는 갓마더 같은 함수지~"

니시키노 마키 : "에?~. SYS_CONNECT_BY_PATH를 쓰면 '호노카 > 니코 > 마키' 처럼 스카우트 된 경로를 텍스트로 예쁘게 찍어낼 수도 있다고. 이건 기본이잖아?"

유키 세츠나 : "맞습니다!! 그런데 만약 니코 선배가 마키의 선배인데, 마키가 다시 니코 선배의 선배가 되는 엄청난 하극상의 모순이 발생하면 ORA-01436 에러가 터집니다! 이때 CONNECT BY에 NOCYCLE 키워드를 넣고, CONNECT_BY_ISCYCLE로 무한 루프의 폭주를 막을 수 있습니다!! 록 온!!"

LEVEL 노드의 깊이(Depth)를 나타내는 가상 컬럼. 루트 노드는 무조건 1이며, 하위로 내려갈수록 1씩 증가한다. LPAD 함수와 결합해 들여쓰기를 할 때 자주 쓴다.
CONNECT_BY_ISLEAF 전개된 노드가 자식이 없는 단말 노드(Leaf, 막내)이면 1, 자식이 있으면 0을 반환하는 가상 컬럼.
SYS_CONNECT_BY_PATH SYS_CONNECT_BY_PATH(컬럼명, '구분자') 형태로 쓴다. 루트 데이터부터 현재 전개된 데이터까지의 전체 경로(Path)를 문자열로 표시해 준다.
CONNECT_BY_ROOT CONNECT_BY_ROOT 컬럼명 형태로 사용. 현재 행의 최상위(루트) 노드 값을 반환한다. 모든 말단 부원 옆에 '최고창립자=호노카'를 찍어주고 싶을 때 쓴다.
CONNECT_BY_ISCYCLE 전개 중에 순환(Cycle) 루프가 발생했는지 알려주는 가상 컬럼. (순환이 발생한 노드면 1, 아니면 0). 단, 이 컬럼은 반드시 `CONNECT BY NOCYCLE` 옵션을 썼을 때만 사용 가능하다.

※ 형제 노드 간의 정렬: ORDER SIBLINGS BY

계층형 쿼리에서 일반적인 ORDER BY를 써버리면, 애써 만들어놓은 계층 구조(트리 모양)가 다 깨지고 냅다 데이터 값 순서대로 섞여버린다. 계층 구조를 그대로 유지하면서, 같은 레벨(형제)끼리만 정렬하고 싶을 때는 반드시 ORDER SIBLINGS BY 컬럼명을 사용해야 한다.

-- [교과서 완벽 반영] 가상 컬럼 및 PATH 지정, 순환(CYCLE) 방지 예시 SELECT 멤버ID, 멤버이름, 직속선배ID, SYS_CONNECT_BY_PATH(멤버이름, ' > ') AS 스카우트경로, CONNECT_BY_ROOT 멤버이름 AS 최고창립자, CONNECT_BY_ISCYCLE AS IS_CYCLE FROM 스쿨아이돌_조직 START WITH 직속선배ID IS NULL CONNECT BY NOCYCLE PRIOR 멤버ID = 직속선배ID; -- 순환 발생 시 폭주 중단!

[실전 4] SYS_CONNECT_BY_PATH (PDF Q8)

Q. (마키 출제) 다음 SQL을 실행했을 때, 말단 부원인 'M007(마키)'까지 영입된 스카우트 경로를 출력한다면 그 결과로 옳은 것은?

[세츠나 해설] 정답은 2번! 순환 참조 에러(ORA-01436)를 막고 폭주를 멈추게 해주는 강렬한 브레이크 같은 녀석입니다! 뜨거운 열정으로 외워주세요!

3. 셀프 조인 (Self Join)의 완벽한 이해

츠루마키 코코로 : "해피! 럭키! 스마일! 오라클 말고 다른 DB에서는 저런 멋진 계층형 쿼리를 못 쓴다며? 그럼 내 직속 밴드 리더 이름 하나 가져오려고 할 때 어떻게 해야 해?!"

오쿠사와 미사키 : "하아... 코코로. 계층형 쿼리가 없던 호랑이 담배 피우던 시절... (효빈광역시 시민들의 트라우마인 두청운수 똥색 버스 시절) 에는 테이블 하나를 마치 두 개인 것처럼 복제해서 조인시키는 셀프 조인(Self Join)을 썼어. 자기 자신과 자기 자신을 조인하는 원초적인 방식이지."

히카와 사요 : "미사키 씨의 말대로입니다. 하지만 셀프 조인은 단계가 깊어질수록 지옥이 됩니다. 상사의 상사를 보려면 테이블을 3번 조인해야 하고, 성능도 급격히 저하되죠. 이때 가장 중요한 절대 규칙은 반드시 '테이블 별칭(Alias)'을 사용해야 한다는 것입니다. FROM 멤버 A, 멤버 B 처럼 별칭을 다르게 주지 않으면, DBMS는 어느 쪽 멤버 테이블인지 분간하지 못해 즉각 에러를 뿜어냅니다."

셀프 조인(Self Join)은 동일한 테이블 내에서 발생되는 연관 관계(예: 직원의 상사가 같은 직원이자 사원 테이블에 존재함)를 해결하기 위해, 하나의 테이블을 물리적으로는 하나지만 논리적으로는 두 개의 테이블인 것처럼 조인하는 기법이다.

  • 목적: 자신의 상사 정보, 같은 부서의 다른 직원 등 동일 테이블 내의 데이터를 참조할 때 사용한다.
  • 필수 조건 (Alias): FROM 절에 동일한 테이블명을 두 번 명시하되, 반드시 서로 다른 테이블 별칭(Alias)을 부여해야 한다.
  • 조인 방식: 문법적으로는 일반적인 INNER JOIN이나 OUTER JOIN과 100% 동일하다. (단지 대상이 자기 자신일 뿐이다).
-- [교과서 완벽 반영] 셀프 조인으로 하위멤버와 직속선배 연결하기 SELECT A.멤버ID AS 하위멤버, A.멤버이름 AS 하위멤버명, B.멤버ID AS 상위선배, B.멤버이름 AS 상위선배명 FROM 스쿨아이돌_조직 A, 스쿨아이돌_조직 B -- ★ A, B 별칭(Alias) 절대 필수! WHERE A.직속선배ID = B.멤버ID;
항목 셀프 조인 (Self Join) 계층 질의 (Hierarchical Query)
구성 방식 테이블 간 조인 계층 전개 (START WITH, CONNECT BY)
깊이 전개 수동 (1단계씩 조인해야 함) 자동 (N단계까지 반복 전개)
가독성 / 성능 나쁨 (테이블 수 증가) / 비효율적 좋음 / 최적화된 내부 알고리즘 활용
[실전 기출 7] 셀프 조인의 활용 (PDF Q9)

Q. (미사키 출제) 하아... 계층 쿼리 없이 옛날 방식인 셀프 조인(Self Join)을 써서 헬로해피 멤버들의 '직속 리더 이름'을 옆에 붙여서 출력하려고 해. 이때 꼭 지켜야 할 조건으로 알맞게 짜여진 SQL은 어느 걸까? 코코로, 제발 아무거나 고르지 마...

  1. FROM 걸즈밴드 JOIN 걸즈밴드 ON A.멤버ID = B.상위리더ID
  2. FROM 걸즈밴드 A JOIN 걸즈밴드 B ON A.상위리더ID = B.멤버ID
  3. FROM 걸즈밴드 A, 걸즈밴드 B WHERE A.멤버ID = B.멤버ID
  4. FROM 걸즈밴드 A LEFT JOIN 걸즈밴드 B ON A.멤버ID = B.상위리더ID
[사요의 보충 해설] 정답은 2번입니다. 물리적으로 동일한 테이블을 쓰기 때문에, FROM 걸즈밴드 A, 걸즈밴드 B 처럼 별칭(Alias)을 주는 것이 필수입니다. 1번은 별칭을 지정하지 않아 에러가 발생하며, 하위멤버의 부모(A.상위리더ID)가 상위멤버의 본인(B.멤버ID)과 매칭되어야 하므로 2번이 논리적으로 완벽합니다.

4. SQL Server에서의 계층 질의 (CTE) 출제주의

미아 테일러 : "Shit! 오라클은 START WITH를 쓰면 되지만, SQL Server는 그런 편리한 전용 문법이 없어! 빌어먹을 마이크로소프트 녀석들. 그럼 SQL Server에서는 어떻게 트리 구조를 그릴까?"

미야시타 아이 : "아하! 아이상, 완전 알 거 같아! 마이크로소프트는 오라클 전용 문법 대신 CTE (Common Table Expression)와 재귀(Recursive) 연산을 조합해서 쓰는 거잖아! WITH문으로 가상의 테이블을 띄워놓고 자기가 자기를 계속 부르는 거 맞지? 효빈광역시 좌석버스(#FF5800)처럼 쌩쌩 돌아가는 아이상의 두뇌 회전 속도를 얕보지 말라고~!"

텐노지 리나 : "리나짱 보드 '놀람!'. 역시 아이 상이야. 앵커 멤버(루트 노드 지정)를 상단 쿼리로 먼저 선언하고, UNION ALL로 중간을 묶은 뒤에, 하단 쿼리인 재귀 멤버(자식 탐색)가 무한 반복하며 꼬리를 무는 구조구나!"

SQL Server는 오라클의 전용 문법인 CONNECT BY를 지원하지 않기 때문에, WITH CTE 구문과 UNION ALL을 이용한 재귀 호출 구조로 계층형 데이터를 구현한다. (SQLD 시험이 오라클 베이스라 깊게는 안 나오지만, 개념 매칭 문제는 PDF 기출 10번처럼 무조건 출제된다!)

  • 앵커 멤버 (Anchor Member): WITH 구문 내의 상단 쿼리. 계층의 시작 위치(루트)를 지정한다. (오라클의 START WITH 역할)
  • UNION ALL: 중간 연결부. 앵커 멤버의 결과와 아래 재귀 멤버의 결과를 반복해서 하나로 합친다.
  • 재귀 멤버 (Recursive Member): WITH 구문 내의 하단 쿼리. 자신이 만든 CTE 가상 테이블을 내부 JOIN하여 자식 노드를 반복적으로 찾아낸다. (오라클의 CONNECT BY 역할)
-- [교과서 완벽 반영] SQL Server의 CTE를 이용한 재귀 계층 질의 WITH BandCTE (멤버ID, 상위리더ID, 멤버이름, [Level]) AS ( -- 1. 앵커 멤버 (루트 노드 지정: 상위리더가 NULL인 항목) SELECT 멤버ID, 상위리더ID, 멤버이름, 1 AS Level FROM 걸즈밴드_조직 WHERE 상위리더ID IS NULL UNION ALL -- 중간 연결부 -- 2. 재귀 멤버 (자식 멤버를 재귀적으로 탐색) SELECT M.멤버ID, M.상위리더ID, M.멤버이름, C.Level + 1 FROM 걸즈밴드_조직 M JOIN BandCTE C ON M.상위리더ID = C.멤버ID ) SELECT * FROM BandCTE ORDER BY Level, 멤버ID;
[아이의 초특급 울트라 천재적인 CTE 재귀 비유! 🌟]
미야시타 아이 : "아까 리나 쨩이 말한 '재귀 탐색'이 헷갈리는 사람들을 위해, 이 천재 아이상이 걸즈밴드 파티 다단계(?) 연락망에 비유해 볼게!"
1. 앵커 멤버 (루트 노드 지정): "제일 먼저! 서클(CiRCLE) 라이브하우스 오너인 마리나 씨가 톡방을 딱! 만드는 거야. 이게 바로 WHERE 상위리더ID IS NULL(상위가 없는 최상위 보스)인 첫 번째 시작점, 앵커(Anchor) 멤버야!"
2. UNION ALL (중간 연결부): "이제 마리나 씨가 직접 뽑은 1차 명단이랑, 밑에 애들이 꼬리를 물고 데려올 연락망을 합쳐야겠지? 이 UNION ALL은 위아래 결과를 하나로 묶어주는 찰떡같은 접착제 역할을 해!"
3. 재귀 멤버 (자식 멤버 반복 탐색): "여기가 진짜 재귀(Recursive)의 핵심! 마리나 씨가 Poppin'Party의 카스미한테 연락하고, 카스미가 Roselia의 유키나한테 연락하고, 유키나가 다시 RAISE A SUILEN의 츄츄한테 연락하는 식으로 꼬리에 꼬리를 무는 거야! 즉, 자기가 만든 가상의 테이블(BandCTE)을 다시 내부 JOIN해서 후배의 후배를 무한루프로 계속 찾아내는 거지!"
"어때? CTE(씨티이)로 밴드 멤버 찾기, 완전 쉽티이(CTE)~? 깔깔깔!"
[실전 기출 8] SQL Server의 계층 질의 (PDF Q10)

Q. (미아 출제) What the... SQL Server에는 START WITH 같은 구문이 없잖아. 이 천재 미아 테일러가 인정하는, SQL Server에서 계층형 질의를 완벽하게 구현하는 방식은 다음 중 어느 걸까? Baby들, 설마 틀리진 않겠지?

  1. START WITH ~ CONNECT BY
  2. 셀프 조인(Self Join)
  3. 일반 서브쿼리(Subquery)
  4. CTE(Common Table Expression) + 재귀(Recursive)
[미아 테일러 해설]
당연히 정답은 4번이지.
오라클 편애주의인 SQLD 시험에서도 이 정도 차이점은 꼬박꼬박 물어본다고. 1번은 완벽하게 오라클(Oracle) 전용 문법이고, SQL Server(MS SQL)에서는 WITH CTE 절 안에서 UNION ALL을 통해 재귀 멤버(Recursive)를 돌리는 방식으로 계층 트리를 만들어낸다는 사실을 꼭 머릿속에 박아둬.
