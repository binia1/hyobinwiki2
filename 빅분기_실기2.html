1. 사분위수(Q1, Q3)와 IQR 이상치 탐지 (제거 vs clip)

👑 나카스 카스미 (수강생): "에리 선배! 이상치(Outlier)를 찾으라는데 왜 자꾸 Q1이랑 Q3을 구해서 1.5를 곱하는 거예요? 그리고 이상치를 '제거하라'는 문제에서 왜 부등호를 < 대신 >=로 반대로 써야 하는 건지 헷갈려 죽겠어요!"

👩‍🏫 아야세 에리 (일타 강사): "카스미, '이상치 자체를 찾을 때'와 '이상치를 버리고 정상 데이터만 남길 때'는 조건식과 연결 기호(| vs &)가 정반대가 돼! 여기서 부등호 하나 잘못 쓰면 0점이니까 아래 공식을 눈에 사진 찍듯 박아두자!"

  • 사분위수와 IQR의 정의: 데이터를 작은 것부터 크기순으로 줄 세웠을 때 25% 지점이 1사분위수($Q_1$), 50% 지점이 중앙값($Q_2$), 75% 지점이 3사분위수($Q_3$)다.
    • $$\text{IQR} = Q_3 - Q_1$$ 은 가운데 절반(50%)의 데이터가 퍼져 있는 폭이다. 평균이나 표준편차와 달리 양 끝의 극단값에 잘 흔들리지 않는 강건한 지표다.
    • df["열"].quantile(0.25)의 기본 계산 방식은 선형 보간(linear)이다. 발문이 별말 없으면 판다스 기본값 그대로 쓰면 된다.
  • 이상치 경계선 공식: $$\text{아래 경계(low)} = Q_1 - 1.5 \times \text{IQR}, \quad \text{위 경계(high)} = Q_3 + 1.5 \times \text{IQR}$$ (1.5라는 숫자는 통계학의 관행이며, 만약 시험 발문이 "1.5 대신 2.0을 곱하라"처럼 다른 배수를 주면 무조건 발문을 따른다!).
  • 🚨 [절대 암기] '이상치 찾기' vs '정상 데이터 남기기(제거)' 조건식 비교:
    • ① 이상치(Outlier) 행을 찾을 때 (바깥쪽, | 또는): 아래 경계보다 작거나(|) 위 경계보다 큰 값이다! (한 숫자 동시에 맨 아래이면서 맨 위일 수는 없으므로 무조건 |를 쓴다!)
      ➡️ outliers = df[(w < low) | (w > high)]
    • ② 이상치를 제거하고 정상 행만 남길 때 (안쪽, & 그리고): 아래 경계 이상(>=)이면서 동시에(&) 위 경계 이하(<=)인 값이다!
      ➡️ kept = df[(w >= low) & (w <= high)]
  • "제거(Drop)"와 "자르기(Clip)"는 완전히 다른 동사다!
    • 발문이 "이상치를 제거하고 평균을 구하라"고 하면 이상치 행을 아예 삭제한 kept 데이터로 다음 계산을 해야 한다 (행 수가 줄어든다).
    • 반면 clip(low, high)는 이상치를 버리지 않고 경계값으로 끌어당겨 바꿔치기할 뿐이라 행 수가 그대로다. 시키지도 않은 clip을 쓰거나 제거 전 원본 데이터로 계산하면 에러도 안 나고 조용히 틀린다!

2. 최소최대 정규화: MinMaxScaler vs 직접 수식 계산

🌸 오토무네 코즈에 (기계치 수강생): "우후후… 히메야, 최소최대 정규화를 하려고 mm.fit_transform(df['콜레스테롤'])을 쳤는데 또 컴퓨터가 차원 오류(ValueError: Expected 2D array, got 1D array instead)라며 화를 내네… 내가 뭘 잘못 누른 걸까…?"

🎮 안요지 히메 (일타 강사): "코즈에 선배! scikit-learn의 모든 스케일러와 머신러닝 모델은 1차원 줄(Series)을 싫어해요! 무조건 대괄호 두 겹 df[['콜레스테롤']](2차원 표)로 감싸서 먹여줘야 작동해요!"

  • 최소최대 정규화(Min-Max Scaling)의 원리: 가장 작은 최솟값을 0.0, 가장 큰 최댓값을 1.0으로 만들고 나머지 모든 값을 그 사이(0~1)에 비례해서 세우는 작업이다. $$\text{MinMax 정규화 수식} = \frac{x - \min(x)}{\max(x) - \min(x)}$$
  • 도구로 쓰기 (MinMaxScaler):
    • from sklearn.preprocessing import MinMaxScaler로 가져온 뒤, mm = MinMaxScaler()로 기계를 만들고 mm.fit_transform(df[["열이름"]])으로 변환한다.
    • 대괄호 두 겹 주의: 안쪽 대괄호는 열 이름 리스트이므로 반드시 df[["콜레스테롤"]]처럼 두 겹으로 넘겨야 한다!
    • fit_transform의 뜻: 데이터에서 최솟값·최댓값 기준을 배우고(fit), 그 기준으로 데이터를 0~1로 변환한다(transform)는 두 동작을 한 번에 수행한다. (나중에 2유형에서는 훈련 데이터에만 fit_transform을 쓰고, 평가 데이터에는 transform만 따로 써야 데이터 누수를 막을 수 있다!).
  • 스케일러 결과 vs 손으로 쓴 수식 결과: 두 값의 차이((manual - df["콜_mm"]).abs().max())를 찍어보면 0.0으로 완벽하게 일치한다!

3. 표준화(Z-score)의 거대한 함정: StandardScaler(ddof=0) vs pandas std(ddof=1)

💧 오사카 시즈쿠 (수강생): "방금 최소최대 정규화는 스케일러랑 손 수식이 똑같았잖아요! 그런데 표준화(Z-score)는 왜 StandardScaler로 돌린 최댓값(3.0631)이랑 제가 판다스 수식 (x - x.mean()) / x.std()로 구한 최댓값(3.0529)이 소수 둘째 자리부터 다른 건가요?! 멘탈이 나갈 것 같아요…!"

🗡️ 카츠라기 이즈미 (일타 강사): "시즈쿠, 바로 여기가 빅분기 제1유형 최대의 크레바스다! StandardScaler는 내부적으로 넘파이(ddof=0, 모표준편차)로 나누고, 판다스의 .std()는 기본값이 ddof=1(표본표준편차)로 나누기 때문이다!"

  • 표준화(Standardization, Z-score)의 원리: 데이터의 평균을 0, 표준편차를 1로 맞추어 단위가 서로 다른 열들을 동일한 잣대 위에 올리는 작업이다. $$Z = \frac{x - \text{평균}}{\text{표준편차}}$$
  • 🚨 왜 두 표준화 값이 다를까? (자유도 ddof의 충돌):
    • StandardScaler() 사용 시: 분모의 표준편차를 구할 때 $N$으로 나누는 모표준편차(ddof=0, 21.0489)를 사용한다. 따라서 최댓값이 3.0631이 나온다.
    • 판다스 수식 (chol - chol.mean()) / chol.std() 사용 시: 판다스 .std()는 $N-1$로 나누는 표본표준편차(ddof=1, 21.1194)가 기본값이다! 분모가 조금 더 크니 나눈 최댓값은 조금 더 작은 3.0529가 나온다.
  • 시험장 행동 강령: 어느 쪽이 맞고 틀린 게 아니라 정의가 다른 것이다!
    ① 발문이 "StandardScaler를 사용하여 표준화하시오"라고 하면 ➡️ StandardScaler()(또는 chol.std(ddof=0))가 정답!
    ② 발문이 "표본표준편차(자유도 n-1)를 이용하여 표준화하시오"라고 하면 ➡️ 판다스 수식 (x - x.mean()) / x.std()가 정답!

6. [합격자 비기 1] groupby · melt · pivot · 멀티인덱스 'shape 예측 8계명'

👑 나카스 카스미 & 🌸 오토무네 코즈에: "선배님들!! groupby, melt, pivot, reset_index, MultiIndex… 이런 거 할 때마다 표가 가로로 찢어졌다가 세로로 길어졌다가 해서 지금 표가 몇 행 몇 열인지 머리가 완전히 하얘져요! 합격자들은 이걸 어떻게 안 헷갈리고 푸는 거예요?!"

🏆 빅분기 고득점 합격자의 [데이터프레임 차원(Shape) 보존 & 변환 8계명]

  1. 데이터 총량 보존의 법칙 (피벗 ↔ 멜트): groupby나 pivot_table로 여러 행을 하나로 뭉개서 통계(평균·합계)를 내는 경우를 제외하면, 단순 형태 변환인 pivot(가로로 넓히기)과 melt(세로로 길게 펴기)는 언제나 (인덱스 개수 × 값 컬럼 개수)라는 전체 데이터 칸의 총량이 100% 똑같이 유지된다! (단, Long format으로 펼 때는 기존 컬럼 이름을 담는 변수 열이 1개 추가되어 컬럼 수가 +1 늘어나는 것만 감안하면 된다).
  2. 멀티인덱스(MultiIndex)의 탄생: df.groupby(["부서", "직급"])처럼 그룹바이를 여러 변수로 묶으면, 결과 표의 왼쪽 인덱스가 2층, 3층짜리 멀티인덱스(MultiIndex)가 되어버려서 나중에 일반 인덱싱으로 값을 꺼내기가 엄청나게 번거로워진다.
  3. 멀티인덱스의 행(Index) 개수 공식: 그룹바이를 3개 변수(col1, col2, col3)로 묶으면, 만들어지는 인덱스의 최대 차원(행 수)은 각 변수의 고유값 개수를 곱한 $\text{nunique}(\text{col1}) \times \text{nunique}(\text{col2}) \times \text{nunique}(\text{col3})$개의 조합이 된다!
  4. 그룹바이에 지정하지 않은 수치 변수의 압축(차원 감소): 예를 들어 col1 ~ col4가 있는 표에서 df.groupby(["col1", "col2"]).mean()을 실행하면, 인덱스는 모든 (col1, col2) 조합이 되고, 그룹바이에 지정되지 않은 나머지 col3, col4는 각 조합당 평균값 딱 1개(스칼라, 0차원)로 압축되어 행 개수가 확 줄어든다!
  5. 멀티인덱스 해독제 (as_index=False 또는 .reset_index()): 멀티인덱스가 꼴보기 싫다면 처음부터 df.groupby(["부서", "직급"], as_index=False).mean()을 쓰거나, 결과 뒤에 .reset_index()를 붙이면 인덱스에 올라가 있던 그룹 변수들이 전부 평범한 열(Long format)로 내려오고 왼쪽 인덱스는 평화로운 0, 1, 2... (RangeIndex)로 초기화된다! (특정 층만 내리고 싶다면 .reset_index(level=0)처럼 지정 가능).
  6. set_index("열")은 reset_index()의 정반대 버튼이다: 평범한 열을 왼쪽 인덱스로 올리고 싶을 때 쓴다.
  7. 수치형 계산의 황금률: 당연한 말 같지만, 더하기·빼기·비율 같은 수치 계산은 무조건 계산할 대상들이 나란히 '컬럼(열)'으로 서 있을 때(Wide format) 계산하기가 제일 편하다! (예: table['Female'] / table.sum(axis=1)).
  8. 모르겠으면 무조건 Long Format(길게 펴기)으로! 시험장에서 표 모양이 꼬여서 도저히 모르겠으면, 문제에서 최종적으로 원하는 행(인덱스)과 열(컬럼)이 뭔지 생각한 뒤 .reset_index()와 pd.melt()로 일단 모든 걸 평평한 1층짜리 Long format으로 다 펴놓고 시작하면 무조건 풀린다!

9. 제1유형 전처리 · 스케일링 · 형태변환 함수 총정리 (러브라이브! 에디션)

오늘 배운 이상치 처리, 스케일링, 결측치 대체, 형태 변환(Shape 보존) 및 시험장 치트키를 한눈에 볼 수 있는 최종 요약표입니다.

분류 함수 / 문법 핵심 기능 및 시험장 주의사항 러브라이브! & 뱅드림! 예시
1. IQR 이상치
(Outliers)		 q1 = s.quantile(0.25)
q3 = s.quantile(0.75)
iqr = q3 - q1		 1사분위수(25%)와 3사분위수(75%)의 차이로 가운데 50%의 퍼짐 폭 계산. low = q1 - 1.5 * iqr
