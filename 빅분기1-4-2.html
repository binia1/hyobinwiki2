05 데이터 분석 방안 (이어서)

5) 소프트웨어개발생명주기(SDLC) 모형 선정 기준

프로젝트 환경에 맞는 적절한 SDLC 모형(폭포수, 프로토타입, 나선형, 반복적 등)을 선정하기 위해 다음을 고려한다.

  • 프로젝트의 규모와 성격
  • 개발에 사용되는 방법과 도구
  • 개발에 소요되는 시간과 비용
  • 개발과정에서의 통제수단과 소프트웨어 산출물 인도 방식
📑 [개념 체크] 분석 방법론 & SDLC 모형

Q1. 다음 중 분석 방법론에 대한 설명으로 옳은 것은?
① 명확한 절차, 방법, 도구, 템플릿, 산출물, 그리고 전문지식이 담긴 매뉴얼을 제공해야 한다.
② 여러 사람들의 내재화된 습득을 체계화한 후 전문가에 의해 형식화되어 생성된다.
③ 일반적으로 계층적 프로세스 모델 형태로 구성 가능하며, 단계, 스텝, 워크패키지 3계층으로 구성된다.
④ 데이터 분석을 효과적으로 수행하기 위하여 분석 절차를 체계적으로 정리한 방법이다.

[정답 및 해설] ④
- ① 분석 방법론은 '어느 정도의 지식만 있으면 활용 가능한 수준의 난이도'를 구성요소로 요구하므로 고도의 전문지식이 담긴 매뉴얼이어야 할 필요는 없습니다.
- ② 노나카 이쿠지로의 지식창조 메커니즘에 따르면, 개인의 암묵지가 형식화를 거쳐 형식지가 되고, 이것이 체계화되어 방법론이 생성됩니다. 전문가가 중간에 가로채는 구조가 아닙니다.(...)
- ③ 계층적 프로세스 모델의 3계층은 단계(Phase), 태스크(Task), 스텝(Step)입니다. 워크패키지는 스텝이 WBS 상에서 대응되는 개념일 뿐입니다.

Q2. 다음 중 소프트웨어개발생명주기에 대한 설명으로 옳은 것은?
① 폭포수 모형은 의사소통을 향상시킨다.
② 나선형 모형은 계획수립, 위험분석, 개발, 고객평가 단계로 구성되어 있다.
③ 원형 모형은 이해하기 쉽고 관리가 용이하다.
④ 반복적 모형은 증분형 모형과 진화형 모형이 존재하며, 진화형 모형의 품질이 더 우수하다.

[정답 및 해설] ②
- ① 의사소통을 향상시키는 것은 시제품을 제공하는 프로토타입 모형입니다. 폭포수는 고객이 마지막에 결과물 보고 뒷목 잡기 딱 좋습니다.(...)
- ③ 이해하기 쉽고 관리가 용이한 것은 고전적 방식인 폭포수 모형입니다. 원형(프로토타입) 모형은 반복적 피드백 때문에 관리가 다소 복잡합니다.
- ④ 증분형과 진화형은 서로 필요에 따른 접근 방식의 차이일 뿐, 특정 모형의 품질이 무조건 우수하다고 단정할 수 없습니다.

4) KDD 분석 방법론

KDD(Knowledge Discovery in Databases)는 1996년 Fayyad가 통계적인 패턴이나 지식을 탐색하는 데 활용할 수 있도록 체계적으로 정리한 프로파일링 기술 기반의 데이터 마이닝 프로세스입니다.[1]

① KDD 분석 방법론의 9가지 프로세스

  1. 분석 대상 비즈니스 도메인의 이해
  2. 분석 대상 데이터셋 선택 및 생성
  3. 데이터에 포함되어 있는 잡음(Noise)과 이상값(Outlier)[2] 등을 제거하는 정제작업이나 전처리
  4. 분석 목적에 맞는 변수를 찾고 필요시 데이터의 차원을 축소하는 데이터 변경(변환)
  5. 분석 목적에 맞는 데이터 마이닝 기법 선택
  6. 분석 목적에 맞는 데이터 마이닝 알고리즘 선택
  7. 데이터 마이닝 시행
  8. 데이터 마이닝 결과에 대한 해석
  9. 데이터 마이닝에서 발견된 지식 활용

② KDD 분석 방법론의 분석절차 (5단계)

데이터 분석은 데이터셋 선택(Selection), 데이터 전처리(Preprocessing), 데이터 변환(Transformation), 데이터 마이닝(Data Mining), 데이터 마이닝 결과 평가(Interpretation/Evaluation) 총 5단계에 걸쳐 진행됩니다.

🧠 [효빈위키 팩폭 해설] 빈효선 전노아의 KDD 무조건 출제 레이어

KDD 5단계 절차(선택 → 전처리 → 변환 → 마이닝 → 평가)는 그냥 시험지에 대놓고 나옵니다. 특히 영문 표기(Selection, Preprocessing, Transformation, Data Mining, Evaluation)와 매칭하는 문제로 뒤통수를 자주 후려치니 철자까지 유심히 봐두셔야 합니다!

  • '이상치/결측치 제거' 키워드가 나오면? → 전처리(Preprocessing) 단계!
  • '차원 축소, 변수 선택, train/test 분리' 키워드가 나오면? → 변환(Transformation) 단계!

단어 하나하나 매칭해서 꼬아 내는 출제 위원들의 사악한 패턴을 역으로 털어버립시다!(...)

5) CRISP-DM 분석 방법론

CRISP-DM(Cross Industry Standard Process for Data Mining)은 계층적 프로세스 모델로서 4계층으로 구성된 데이터 마이닝 프로세스입니다.[3]

6) SEMMA 분석 방법론

SEMMA(Sample, Explore, Modify, Model and Assess)는 SAS Institute[4]의 주도로 만들어진 기술과 통계 중심의 데이터 마이닝 프로세스입니다.

① SEMMA 분석 방법론의 특징

  • SAS Institute의 데이터 마이닝 도구(Enterprise Miner)와 손쉽게 접목하여 활용할 수 있습니다.
  • 비즈니스적 관점보다는 주로 데이터 마이닝 프로젝트의 모델링 작업 및 기술적 프로세스에 중점을 두고 있습니다. (업무 이해나 전개 단계 따위 쿨하게 생략하고 오직 데이터 조지는 것에만 집중하는 장인정신...)

② SEMMA의 5단계 절차

(Sample)"] --> Explore["2. 탐색
(Explore)"] Explore --> Modify["3. 수정
(Modify)"] Modify --> Model["4. 모델링
(Model)"] Model --> Assess["5. 평가
(Assess)"] Assess -.->|Feedback| Sample style Sample fill:#D9E1F2,stroke:#4472C4,stroke-width:2px style Explore fill:#FCE4D6,stroke:#C65911,stroke-width:2px style Modify fill:#FFF2CC,stroke:#D6B656,stroke-width:2px style Model fill:#E2F0D9,stroke:#385723,stroke-width:2px style Assess fill:#E1D5E7,stroke:#6C8EBF,stroke-width:2px
  • Sample (샘플링): 분석에 필요한 표본 데이터를 추출하고 구성하는 단계
  • Explore (탐색): 데이터의 현황을 파악하고 비정상적인 특징을 탐색하는 단계
  • Modify (수정): 변수 생성, 선택, 변환을 통해 데이터를 정제하는 단계
  • Model (모델링): 다양한 통계 및 머신러닝 알고리즘을 적용하여 모형을 구축하는 단계
  • Assess (평가): 구축된 분석 모형의 성능을 평가하고 검증하는 단계
🎓 [효빈위키 기적의 합격 패스 팁] 6호선 라세나의 족집게 강의
  • CRISP-DM의 4계층 위계: 단계 → 일반화 태스크 → 세분화 태스크 → 프로세스 실행 순서는 무조건 기억하십시오. 엉뚱한 단어 끼워 넣기로 자주 낚시질을 합니다.
  • CRISP-DM 6단계 순서 암기: 비이 → 데이 → 데준 → 모 → 평 → 전 (비즈니스 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개) 앞 글자만 따서 입에 붙여두세요. 특히 '평가(Evaluation)' 단계 다음이 '전개(Deployment)'라는 점을 기억하셔야 선후 관계 문제를 맞힐 수 있습니다!
  • CRISP-DM vs KDD 짝꿍 매칭: 시험에서 가장 매력적인 오답 선지는 "CRISP-DM의 데이터 이해 단계는 KDD의 데이터 전처리 단계와 매핑된다"입니다. 땡! 틀렸습니다. CRISP-DM의 데이터 이해는 KDD의 데이터셋 선택(Selection)과 짝꿍이며, 데이터 준비가 KDD의 전처리+변환과 매핑됩니다. 이거 헷갈리면 바로 털립니다!
  • SEMMA의 핵심: 이름 자체가 5단계 순서(S-E-M-M-A)입니다. CRISP-DM이나 KDD와 달리 비즈니스 이해(업무 이해) 단계가 명시적으로 존재하지 않고, 기술적 통계 분석에 집중된 SAS 지향적 방법론이라는 차이점을 묻는 서술형 오답 고르기도 빈출 유형입니다.
📑 [개념 체크] 데이터 마이닝 방법론 비교

Q1. 다음 중 KDD 분석 방법론에 대한 설명으로 틀린 것은?
① 데이터 마이닝 외 다른 분야에는 응용하기 어렵다는 단점이 있다.
② 데이터에서 패턴을 찾는 과정을 통계적 프로세스로 제시한다.
③ 데이터셋 선택, 데이터 전처리, 데이터 변환, 데이터 마이닝, 데이터 마이닝 결과 평가 총 5단계에 걸쳐 진행된다.
④ 체계적으로 정리한 프로파일링 기술 기반의 데이터 마이닝 프로세스이다.

💡 정답: ① (KDD 분석 방법론은 데이터 마이닝뿐만 아니라 기계학습, 인공지능, 패턴인식, 시각화 등 다양한 분야에 널리 응용할 수 있는 범용적인 프로세스입니다. 지가 뭔데 다른 데 못 쓰겠다고 제한을 둡니까?)

Q2. 다음 중 CRISP-DM 분석 방법론에 대한 설명으로 틀린 것은?
① 데이터 탐색과 이해 및 데이터를 통한 문제 인식과 해결이 가능하다.
② 비즈니스 요구사항에 맞게 데이터 마이닝을 반복적으로 수행할 수 있다.
③ 계층적 프로세스 모델로써 3계층으로 구성된 데이터 마이닝 프로세스이다.
④ 업무 이해, 데이터 이해, 데이터 준비, 모델링, 평가, 전개 총 6단계에 걸쳐 진행된다.

💡 정답: ③ (CRISP-DM의 계층 구조는 3계층이 아니라 4계층(단계 → 일반화 태스크 → 세분화 태스크 → 프로세스 실행)으로 구성되어 있습니다. 3계층은 바로 뒤에 나올 '빅데이터 분석 방법론'의 위계 구조입니다!)

Q3. 다음 중 SEMMA 분석 방법론에 대한 설명으로 틀린 것은?
① SAS Institute의 데이터 마이닝 도구와 손쉽게 접목하여 활용할 수 있다.
② 응용 서비스 개발을 위한 3계층으로 구성되었다.
③ 주로 데이터 마이닝 프로젝트의 모델링 작업에 중점을 두고 있다.

1) 빅데이터 분석 방법론 개요

① 분석 기획 (Planning) 단계

  • 비즈니스 이해 및 범위 설정: 도메인 파악 (매뉴얼, 전문가 도움), 프로젝트 범위 명확화를 위한 구조화된 명세서 작성.
  • 프로젝트 정의 및 계획 수립: 모형 평가 기준 설정, KPI(핵심성과지표)[5] 구체화, 수행 계획서 작성, WBS(작업분할구조) 작성.
  • 프로젝트 위험계획 수립: 발생 가능한 위험 식별, 영향도/빈도 우선순위 설정. 대응 전략 4가지: 회피(Avoidance), 전이(Transfer), 완화(Mitigation), 수용(Acceptance). (위험이 닥쳤을 때 쌩까거나(수용) 남 탓으로 넘기거나(전이) 도망치는(회피) 유연한 생존 전략...)

② 데이터 준비 (Preparing) 단계

  • 필요 데이터 정의: 전사 차원 데이터 정의, 데이터 정의서 작성. 내부/외부 데이터 획득 시 법적/보안 문제 사전 파악. (원시 데이터[6] 파악).
  • 데이터 스토어 설계: 논리적/물리적 분리 설계. (정형 데이터는 주로 RDBMS, 비/반정형은 하둡/NoSQL 활용[7]).
  • 데이터 수집 및 정합성 점검: 크롤링, ETL 도구, API 등 다양한 도구로 수집[8]. 메타 데이터 및 데이터 사전 정합성 점검 및 품질 보완.

③ 데이터 분석 (Analyzing) 단계

  • 분석용 데이터 준비: 비즈니스 룰 파악, 데이터 가공 및 분리.
  • 텍스트 분석: 업무 도메인에 맞는 용어사전[9]을 구축하여 텍스트 데이터 추출 및 기법 적용.
  • 탐색적 분석 (EDA): 기초 통계량 산출. 시각화(Visualization)를 EDA 도구로 적극 활용하여 데이터 형상/특성을 파악한다.
  • 모델링: 학습용(Train)과 테스트용(Test) 분할, 교차검증/앙상블 설정. 알고리즘 설명서는 의사코드(Pseudocode) 수준으로 상세히 작성.
  • 모델 평가 및 검증: 목표 미달 시 모형 튜닝(Hyperparameter Tuning). 모형의 객관성/실무 적용성을 최종 검증하는 프로세스이다.[10]

④ 시스템 구현 (Developing) 단계

  • 설계 및 구현: 시스템/데이터 아키텍처, UI 설계. BI 패키지나 프로그래밍을 통한 모형 구현.
  • 시스템 테스트 및 운영: 단위/통합/시스템 테스트 실시. 시스템 운영자 및 사용자를 대상으로 필요한 교육 실시. 시스템 운영계획 수립.

⑤ 평가 및 전개 (Deploying) 단계

  • 모델 발전계획 수립: 생명주기 설정, 주기적 평가 실시, 업데이트 자동화 방안 수립. (한 번 만들고 유기하면 모델이 썩어 문드러집니다...)
  • 프로젝트 평가 및 보고: 정량/정성적 성과 평가서 작성, 지식/프로세스 산출물 자산화.
💡 [효빈위키 족집게 레이어] 고나미가 잡아주는 태스크 소속 타짜 방어전!
  • WBS 작성, KPI 설정, 위험 대응(회피/전이/완화/수용): 분석 기획(Planning) 단계!
  • 데이터 정의서 작성, 데이터 스토어 설계, 수집/정합성 점검: 데이터 준비(Preparing) 단계! ('데이터 정의서'를 분석 기획에 슬쩍 넣는 낚시 주의)
  • 텍스트 분석, EDA(시각화), 모델 분할/튜닝(의사코드), 모형 평가: 데이터 분석(Analyzing) 단계!
  • 아키텍처 설계, 각종 테스트, 사용자 교육: 시스템 구현(Developing) 단계! ('사용자 교육'을 분석 단계에 섞어놓으면 쳐내세요.)
  • 모델 발전계획 수립 (생명주기, 자동화): 평가 및 전개(Deploying) 단계!

5) 데이터 거버넌스 (Data Governance)

① 데이터 거버넌스의 필요성 및 정의

개별 시스템 단위로 관리하면 중복, 비표준화로 인해 데이터 거대한 쓰레기통이 된다. 전사 차원의 모든 데이터에 대하여 정책, 지침, 표준화, 관리 체계를 수립하고 운영하기 위한 프레임워크와 저장소를 구축하는 것이다.

② 데이터 거버넌스의 주요 관리 대상 3가지 (★단골 출제)

  • 마스터 데이터 (Master Data): 마스터 파일을 형성하는 핵심 데이터, 데이터 처리/조작을 위한 기본 데이터. (예: 학생부의 이름, 생년월일, 주소)[14]
  • 메타 데이터 (Meta Data): 데이터에 대한 구조화된 데이터, 다른 데이터를 설명하기 위해 사용되는 데이터. (예: 영상 파일의 생성 날짜, 작성자, 크기 등)[15]
  • 데이터 사전 (Data Dictionary): 자원관리를 위해 자료의 이름, 표현 방식, 의미, 관계 등을 저장해놓은 데이터.

② 데이터 분석 교육 방향 및 체계

단순한 도구(Tool) 사용법 교육이 아닌, 분석적 사고와 문제해결 역량을 강화하는 방향으로 진행한다. 기획자에게는 큐레이션 교육, 실무자에게는 기법 교육, 기존 업무자에게는 기회 발굴 교육을 진행한다.

08 데이터 분석 수준진단

1) 데이터 분석 수준진단 개요

조직의 현 상태에 대한 명확한 점검을 통해 준비도(Readiness) 6영역과 성숙도(Maturity) 3부문을 평가한다. (지피지기면 백전백승, 우리 조직이 쪼렙인지 만렙인지 알아야 처방을 짠다.)

2) 분석 준비도 (Readiness) 6대 영역

데이터 분석 업무 도입을 목적으로 현재 수준을 파악하기 위한 진단. (앞 글자 따서 업·인·기·데·문·이)

  • 업무 (Business): 분석 업무 파악
  • 인력 및 조직 (Organization): 분석 전담 조직 및 인력
  • 기법 (Technique): 분석 기법 적용
  • 데이터 (Data): 분석 데이터 확보
  • 문화 (Culture): 분석 기반 문화
  • IT 인프라 (IT Infrastructure): 분석을 위한 환경

※ 일정 수준 충족 시 업무 도입, 미달 시 환경부터 먼저 조성.[18]

3) 분석 성숙도 (Maturity) 모델 (★단골 낚시터)

비즈니스 부문, 조직/역량 부문, IT 부문 3개를 대상으로 도입 → 활용 → 확산 → 최적화 4단계로 진단한다.[19]

단계비즈니스 부문조직 및 역량 부문IT 부문 (★핵심 기술 키워드)
1. 도입 단계 실적 분석, 통계, 정기 보고 일부 부서 수행, 담당자 존재 데이터 웨어하우스(DW), 데이터 마트(DM), OLAP[20]
2. 활용 단계 미래 결과 예측, 시뮬레이션 전문 담당 부서 수행, 관리자 분석 수행 실시간 대시보드, 통계 분석 환경
3. 확산 단계 전사 성과 실시간 분석, 프로세스 혁신 3.0 전사 모든 부서 수행, 데이터 사이언티스트 확보 빅데이터 관리 환경, 시뮬레이션, 비주얼 분석
4. 최적화 단계 전략 연계, 성과 기여 데이터 사이언스 그룹, 경영진 분석 활용 분석 협업 환경, 분석 샌드박스(Sandbox)[21]

4) 분석 수준진단 결과 (사분면 분석)

준비도(Y축)와 성숙도(X축)를 교차하여 4가지 유형으로 포지셔닝하고 미래 전략을 세운다.

위치유형설명
1사분면 (우상단)확산형준비도 높음, 성숙도 높음. 전사적인 지속 확산.
2사분면 (우하단)도입형준비도 낮음, 성숙도 높음. 분석 업무/기법은 부족하나 조직/환경 등 성숙도는 높음. 도입 시급.
3사분면 (좌하단)준비형준비도 낮음, 성숙도 낮음. 사전 준비가 우선.
4사분면 (좌상단)정착형준비도 높음, 성숙도 낮음. 인력/기법 등은 준비되었으나 조직적 정착이 필요.
🎒 [효빈위키 팩폭 해설] 라미의 좌표 찍기 꿀팁!

준비도(Y축)와 성숙도(X축)의 위치를 바꾸거나 사분면을 뒤집어놓고 묻는 낚시가 아주 악질적이에요. 1사분면(준비/성숙 모두 만렙)은 '확산형'! 이것만 기준점으로 잡아두면 나머지는 풀기 쉽습니다.

📝 [개념 체크] 수준진단 모델

Q1. 다음 중 분석 준비도에 대한 설명으로 틀린 것은?
① 비즈니스 부문, 조직 및 역량 부문, IT 부문 총 3개 부문을 대상으로 실시한다.
② 조직 내 데이터 분석 업무 도입을 목적으로 현재 수준을 파악하기 위한 진단방법이다.
③ 총 6가지 영역을 대상으로 현재 수준을 파악한다.
④ 각 진단 결과 전체 요건 중 일정 수준 이상 충족하면 데이터 분석 업무를 도입한다.

💡 정답: ① (3개 부문을 대상으로 실시하는 것은 분석 성숙도 모델입니다. 분석 준비도는 6대 영역(업/인/기/데/문/이)을 봅니다.)

Q2. 다음 중 분석 성숙도 모델에 대한 설명으로 옳은 것은?
① 최적화 단계에서는 데이터 사이언스 그룹, 경영진 분석 활용, 전략 연계를 비즈니스 부문에서 수행한다.
② 확산 단계에서는 전사 차원에서 분석을 관리하고 공유한다. (※해설: 도입이 아니라 확산의 정의)
③ 확산 단계에서는 전사 성과 실시간 분석, 프로세스 혁신 3.0, 분석규칙 관리, 이벤트 관리를 IT 부문에서 수행한다. (※해설: 해당 업무는 비즈니스 부문)
④ 도입 단계에서는 전문 담당부서에서 수행, 분석기법 도입, 관리자가 분석 수행을 조직 및 역량 부문에서 담당한다. (※해설: '활용 단계'의 설명)

💡 정답: ① (단계가 올라갈수록 만렙이 된다는 걸 표와 매칭시켜야 풀 수 있는 초고난도 문제입니다!)

각주

  • [1] 데이터 마이닝, 기계학습, 인공지능, 시각화 등에 응용 가능하며 통계적 프로세스로 제시한다.
  • [2] 이상값(Outlier): 일반적인 추세에서 많이 벗어난 튀는 값.
  • [3] 문제 인식과 해결이 가능하며 비즈니스 요구사항에 맞게 반복 수행 가능하다.
  • [4] 미국의 통계분석 소프트웨어 기업.
  • [5] KPI: 핵심성과지표 (Key Performance Indicator).
  • [6] 원시 데이터(Raw Data): 수집된 데이터의 초기 형태로 가공/구조화되지 않은 상태.
  • [7] 정형 데이터는 RDBMS를, 비/반정형은 하둡이나 NoSQL을 이용한다.
  • [8] 다양한 도구를 활용하여 수집하고 데이터 스토어에 저장한다.
  • [9] 텍스트 마이닝 할 때 사전 정비를 안 해두면 엉뚱한 키워드만 뽑히다 망한다.
  • [10] 데이터 분석 목적과 데이터셋 특성에 따라 모형 평가 방법이 달라진다.
  • [11] 업무 프로세스, 정책 및 정보를 만들고 관리하는 지속적인 프로세스.
  • [12] 집중형, 기능형, 분산형 조직구조를 의미.
  • [13] 라이브러리 (Library): 공통으로 재사용할 수 있는 부분 기능들을 모아 놓은 것.
  • [14] 학생부 데이터에서 이름, 생년월일, 주소, 전화번호 등.
  • [15] 영상 파일에 대한 생성 날짜, 시간, 작성자, 크기 등. (데이터를 위한 데이터!)
  • [16] 여러 정보를 수집, 선별하고 새로운 가치를 부여해 배포.
  • [17] 여러 웹서비스 업체 콘텐츠 융합. (공공 API 긁어모아 버스 앱 만들기).
  • [18] 데이터를 업무 및 의사결정에 활용하기 위해 어느 정도 준비가 되어 있는지 점검하는 체계.
  • [19] 데이터를 얼마나 잘 수집, 분석, 소비 및 채택할 수 있는지가 성숙도를 결정한다.
  • [20] OLAP: 사용자가 대용량 데이터를 쉽고 다양한 관점에서 추출 및 분석하게 지원.
  • [21] 샌드박스(Sandbox): 보호된 영역 내에서 프로그램을 독립 작동시키는 보안 모형.
