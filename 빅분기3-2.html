01 분석 모형 선정

1) 분석 모형 선정 필요성

  • 분석 기법 또는 분석 알고리즘을 적용하기 전에 분석 모형에 대한 선정이 우선 필요하다.
  • 분석이 필요한 데이터 속성을 세부적으로 파악, 처리한 뒤에 적합한 분석 기법을 선택하게 된다.
  • 데이터가 준비되어 있지 않다면 사전 분석 목적을 정확하게 파악해야 문제 인식과 데이터 준비에 따른 모형 선정을 수월하게 진행할 수 있다.

▶ 분석 목적 설정

빅데이터 분석은 통계에서 분석했던 방식과 함께 기존 통계 방식으로 분석할 수 없던 것들도 분석한다.

graph TD A(("분석 목적")) --> B("요약") A --> C("인과관계 파악") A --> D("예측") A --> E("의사결정") A --> F("불확실성 해소") style A fill:#4a86e8,stroke:#333,stroke-width:2px,color:#fff
  • 1. 의사 결정: 여러 대안 중에서 하나의 행동을 고르는 일을 해내는 정신적 지각 활동. 최종적으로 하나의 선택과 결과가 도출된다.
  • 2. 불확실성 해소: 의사결정의 가장 큰 문제는 불확실성이며, 분석을 통해 이를 제어한다면 시장 대응에 큰 도움이 된다.
  • 3. 요약: 데이터 요약을 통해 현 상황을 쉽고 빠르게 파악 가능하며 다음 대응 방안을 생각할 수 있다.
  • 4. 인과관계 파악: 단순 요약을 넘어 데이터 간 연관관계 분석으로 원인과 결과를 파악하여 세부적 판단을 내린다.
  • 5. 예측: 원인과 결과의 패턴을 파악하면 향후 미래에 생길 결과에 대한 대비(예측)가 가능해진다.
[참고/날개 📌] 빅데이터 분석 근본 목적
과거 데이터를 토대로 원인에 대해 분석하고 결과로 미래를 예측하는 것. 검색키워드라는 '후행성 데이터'로 '왜 사람들이 그것을 알고 싶어할까?' 분석을 통해 미래를 예측하는 '선행성' 성격도 가진다.

2) 분석 모형 선정 프로세스

분석 모형 선정은 다음 순서의 사전 단계들을 수행하며 진행한다.

  1. 문제요건 정의 또는 비즈니스 이해에 따른 대상 데이터 선정과 분석 목표/조건 정의
  2. 데이터 수집, 정리 및 도식화
  3. 데이터 전처리 (정제, 종속/독립변수 선정, 변환, 통합, 축소 등)
  4. 최적의 분석 모형 선정

02 분석 모형 정의

[참고/날개 📌] 분석 모형: 예측 분석 모형, 현황 진단 모형, 최적화 분석 모형

1) 분석 모형 정의와 종류

  • ① 예측 분석 모형: "어떤 일들이 발생할 것인가?"
    적조, 날씨, 주가, 쇼핑아이템 추천 등 가설을 기반으로 미래 현상을 사전에 분류하고 예측한다.
  • ② 현황 진단 모형: "과거에 어떠한 상황이 왜 어떻게 일어났는가? 현재 상태는?"
    과거 데이터를 통해 현재 상황을 객관적으로 진단하고 이해하는 데 활용한다.
  • ③ 최적화 분석 모형: "어떻게 하면 원하는 결과가 일어날 수 있을까?"
    제한된 자원, 환경 내에서 최대의 효용성과 이익을 생성하기 위해 모델을 최적화한다.

2) 분석 모형 정의를 위한 사전 고려사항

분석 모형을 정의하기 전, 분석이 실제 추진될 수 있을지 가능성을 타진하는 평가 기준표 작성이 필요하다. 추진 시급성과 구현 가능성만으로도 사전 판별 기준으로 활용 가능하다.

기준판단 근거
필요성개인이나 기관 관점에서 분석 과제가 필요한지 판단
파급효과정성적, 정량적 기대효과의 정도 판단
추진 시급성당장 해소되어야 할 현안 여부, 장기과제 성격 분리
구현 가능성과제를 구현함에 있어서 어려움이 없는지 현실성 판단
데이터 수집 가능성데이터 확보, 구매 등 제약사항 판단
모델 확장성전체 데이터 모델로 확장 가능한지 판단

▶ 상향식 vs 하향식 접근법 (★단골 출제)

  • ① 상향식(Bottom-up) 접근: 문제 정의가 어려울 경우 많은 양의 데이터 분석을 통해 숨겨진 인사이트를 도출한다. 의사결정 지점으로 진행하는 과정에서 과제를 발굴한다.
  • ② 하향식(Top-down) 접근: 문제 정의가 명확하게 가능할 시 사용한다. 어떻게 수익을 낼 것인가 하는 비즈니스 모델, 벤치마킹을 통한 외부 참조 모델, 상세 설명이 포함된 분석 유스케이스 기반으로 과제를 하향식으로 도출해 낸다.

  • 하향식(Top-down): 걸즈 밴드 크라이의 프로듀서가 "다이아몬드 더스트를 음원 1위로 만들어!"라고 확고한 목표(문제 정의)를 내렸습니다. 그러면 다른 1위 밴드들은 어떻게 했는지(외부 참조 모델 벤치마킹), 수익은 어떻게 낼지(비즈니스 모델) 위에서 아래로 기획을 내리찍는 방식입니다. 대부분의 까라면 까는 직장 업무가 이 방식이죠.
  • 상향식(Bottom-up): 도대체 문제가 뭔지 모를 때 씁니다. 일단 유튜브 조회수 로그 데이터 10만 건을 파이썬으로 긁어모아 분석해 봤더니, "어? 유독 니나가 화를 내는 장면에서만 리텐션(시청 지속시간)이 폭증하네?" 하고 숨겨진 패턴(인사이트)을 바닥에서부터 건져 올리는 방식입니다. 데이터의 바다에서 보물을 찾는 거죠!

03 분석 모형 구축 절차

데이터 분석에 대한 절차와 방법을 체계적으로 구성하는 것이 중요하다.

1) 분석 시나리오 작성

  • 분석 과정과 결과가 어떻게 활용되는지 명확히 이해하기 위해 작성.
  • 분석 대상, 범위, 해결할 문제와 목표, 필요한 데이터, 절차, 분석 기법 등 세부사항을 꼼꼼하게 정의한다. 기존 유사 시나리오를 참고할 수 있다.

2) 분석 모형 설계

분석 목적을 구현하기 위한 방법론을 설계하는 단계이다. 데이터 표준화 방법, 수집 항목, 검증 통계 기법 등을 사전에 확인한다.

  • 데이터 분리: 분석용 데이터를 훈련용(Train)과 테스트용(Test)으로 분리하여 과대적합을 막고 자체 검증한다.
  • 테스트 데이터 비율은 전체 데이터의 30% (7:3)가 일반적이나, 데이터가 충분히 많으면 6:4 또는 5:5로 분리하여 선정할 수도 있다.

3) 분석 모델링 설계와 검정 (가설검정 방법)

[참고/날개 📌] 통계적 가설: 모집단의 모수를 이용해 나타낸 주장 (예: "여자의 평균 신장은 180이다")
[참고/날개 📌] 귀무가설(영가설, $H_0$): 대립가설에 상반되는 가설로서, 기각되는 것이 예상되어 세워진 밋밋한 가설.

가설검정은 다음 5단계의 절차를 거친다.

  • ① 유의수준 결정, 귀무가설/대립가설 설정: 가설검정은 기본적으로 "귀무가설이 옳다"는 가정하에 시작한다. 대립가설은 연구자가 진짜로 입증하고 싶은 가설이다. 유의수준($\alpha$)은 기각역들의 합이며 오류의 허용 한계다.
  • ② 검정통계량 설정: 귀무가설이 참이라는 가정 아래 얻은 통계량 식으로, 기각 여부를 결정하는 기준이다. 계산식: $\frac{\text{(표본평균)} - \text{(모평균)}}{\text{표본 표준오차}}$
  • ③ 기각역(Rejection Region) 설정: 확률분포에서 귀무가설을 기각하는 치명적인 영역. 여기에 통계량이 꽂히면 귀무가설은 아웃이다.
  • ④ 검정통계량 계산 및 ⑤ 의사결정: 계산한 통계량을 기각역(임계치)과 비교한다.

통계학 파트에서 가장 짜증 나는 '귀무가설($H_0$)'과 '대립가설($H_1$)'의 개념은 이 한 줄만 기억하세요. 귀무가설은 '노잼(차이 없음, 원래 그런 거)', 대립가설은 '내가 증명하고 싶은 꿀잼(차이 있음, 새로운 주장)'입니다.

효빈광역시의 신규 대중교통망 노선을 설계하면서, 기존 버스 배차 간격 데이터를 뜯어본다고 가정해 보죠.

  • 귀무가설($H_0$): "정류장의 배차 간격을 5분 단축해도 일일 탑승객 수에는 유의미한 차이가 없을 것이다." (노잼, 예산 지원 못 받음)
  • 대립가설($H_1$): "배차 간격을 단축하면 일일 탑승객 수가 유의미하게 폭발적으로 증가할 것이다!" (우리가 진짜로 검증해서 결재 서류에 당당하게 적고 싶은 내용)

수집한 데이터로 $Z$-값을 굴려서 이 값이 '기각역'에 뚝 떨어지면, "거 봐! 내 말이 맞잖아!" 하면서 귀무가설을 쓰레기통에 버리고 대립가설을 채택하는 짜릿한 과정을 거치게 된답니다! 물론 "다르다"고만 했으면 양쪽을 다 보는 양측검정, "더 많다!"고 찍었으면 우측검정(단측검정)을 써야겠죠?

4) 분석 모델링 설계와 검정 (기술 검토)

  • 데이터 전처리 과정을 마치면 종속 변수의 유무에 따라 사용할 알고리즘이 극명하게 갈린다.
  • 종속 변수(정답지)가 있으면 회귀/분류 같은 지도학습을 쓰지만, 종속 변수가 없으면 사용할 수 있는 알고리즘이 군집, 연관 법칙(비지도학습) 등으로 강하게 제한된다.

02 데이터 분할

모형을 구축하고 성능을 검증하기 위해, 수집한 애지중지한 전체 데이터를 학습(Train), 평가(Validation), 테스트(Test) 3분할로 쪼개어 사용한다.

  • ① 학습(Training) 데이터: 데이터를 학습하여 분석 모형을 만드는 데 직접 사용되는 문제집 데이터이다. 모델 성능에 직결되므로 양과 다양성이 보장되어야 한다.

수집한 피 같은 데이터를 100% 전부 학습(Training)에만 쏟아부으면 어떻게 될까?

AI 모형이 훈련 데이터의 '정답'만 통째로 달달 외워버려서, 처음 보는 실전 데이터가 들어오면 뇌정지가 오는 '과대적합(Overfitting)' 대참사가 발생해. 마치 운전면허 필기시험 기출문제집의 답 번호만 외워서 모의고사 100점을 받았지만, 실제 도로에 나가면 신호등도 못 보고 차를 박아버리는 꼴이랑 똑같지!(...)

그래서 뱅드림! 의 로젤리아(Roselia)가 완벽한 라이브를 위해 실전처럼 리허설을 하듯이, 전체 데이터의 일부를 떼어내어 '평가(Validation)'용 모의고사로 활용하며 모형이 제대로 원리를 이해하고 있는지 중간 점검을 빡세게 해줘야 해!
